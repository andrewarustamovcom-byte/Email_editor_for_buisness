# Архитектура прямого подключения

Последнее решение владельца заменяет предыдущие требования к серверному хранению ключа и модели Алисы: облачная нейросеть с бесплатной API-квотой, личный ключ в браузере, без backend и аренды ВМ. Текущий провайдер — Groq, модель `openai/gpt-oss-120b`. Однократное сохранение личного ключа заменяет прежнюю установку без ввода ключа.

```mermaid
sequenceDiagram
    participant U as Пользователь
    participant C as Gmail content script
    participant W as MV3 worker
    participant S as chrome.storage.local
    participant G as Groq API
    U->>W: Сохранить ключ на странице настроек
    W->>S: Ключ, только trusted contexts
    U->>C: Проверить выбранный черновик
    C->>C: Снимок + revision + SHA-256
    C->>W: Текст и явно выбранная история
    W->>W: Строгий контракт и проверка хеша
    W->>S: Зарезервировать локальные лимиты
    W->>G: Фиксированный промпт + данные + JSON Schema
    G-->>W: Структурированный ответ
    W->>W: Проверить схему и точные цитаты
    W-->>C: Замечания, без ключа
    U->>C: Принять или отклонить правку
    C->>C: Проверить актуальность; точечная замена
```

Системный промпт хранится в `packages/prompts/email-review.ru.md` и включается в service worker при сборке. Страница Gmail не может заменить его произвольной инструкцией. HTML не отправляется. Контракт передаёт requestId, editorId, revision, snapshotHash, тему/текст, выбранные сообщения с id/date, полноту истории, язык, дату, timezone и разрешённые категории. Ключ в этих данных отсутствует.

## Схема ответа

Worker делает `POST https://api.groq.com/openai/v1/chat/completions`, фиксирует модель, `max_completion_tokens=3000`, `reasoning_effort=low`, `stream=false` и `response_format=json_schema` со `strict=true`. Используется структурная схема с required/additionalProperties=false; ограничения длины и прочие более строгие проверки выполняются Zod после ответа. Groq документирует [поддержку структурированного вывода](https://console.groq.com/docs/structured-outputs) для выбранной модели.

Ответ принимается только при finish_reason=stop, наличии содержимого и отсутствии отказа модели. Размер HTTP-ответа ограничен 128 000 байт. Некорректный JSON, неподтверждённые цитаты и ссылки на невыбранную историю отклоняют весь ответ. Проверка цитаты подтверждает источник, а семантическую правильность предложения оценивает пользователь. Нет истории — agreements=insufficient. Нет замечаний в пределах данных не означает проверку всей переписки.

## Ключ и локальные лимиты

Запись ключа разрешена только сообщению от собственной options.html. Content script может запросить анализ и обезличенный статус, но не изменить/прочитать ключ. При старте worker для chrome.storage.local устанавливается `TRUSTED_CONTEXTS`. Хранилище не синхронизируется; там только ключ и числовые счётчики, без писем, истории и результатов.

Операции резервирования сериализуются для всех вкладок. До fetch записываются расход, число попыток и время следующего запроса. Повторный worker читает их заново. Базовые пределы: 60 секунд между попытками, 30 в сутки UTC, дневной резерв 200 000, общий 2 000 000. Резерв — UTF-8 байты полного payload + максимум выхода + запас; он консервативен и не является токенизатором/биллингом Groq. После ошибки резерв не возвращается и автоматического повтора нет. Повреждение счётчиков или ошибка записи блокируют внешнюю попытку. Замена/удаление ключа не сбрасывает расход.

Владелец профиля может очистить локальные данные; другие приложения могут использовать тот же ключ. Поэтому это личное ограничение, а не глобальная защита аккаунта или гарантия нулевого счёта. Бесплатность определяется планом Free у Groq. Расширение не включает оплату и не меняет тариф.

## Канонический текст и безопасные правки

Обход DOM создаёт строку и соответствие каждого UTF-16 code unit началу/концу в текстовом узле. Блоки и br дают LF; CRLF/CR преобразуются в LF, NBSP — в обычный пробел. Остальные пробелы не схлопываются, Unicode NFC/NFKC не применяется. Emoji сохраняются как суррогатные пары; якорь не может разрезать такую пару. Синтетические переносы имеют null-позиции.

Исключаются `.gmail_signature`, `[data-smartmail=gmail_signature]`, `.gmail_quote`, blockquote, contenteditable=false, script/style и явно скрытые узлы. Необычную подпись без этих маркеров нужно проверить в реальном Gmail.

Позиции вычисляются кодом по точной цитате и соседнему контексту. Неоднозначная цитата блокирует замену. Каждый редактор имеет отдельный id и монотонный revision; MutationObserver замечает изменение, включая возвращение к исходному тексту. Перед применением проверяются текущие тема/текст/revision и необработанные мутации. Закрытый редактор считается устаревшим.

Автоматическая замена разрешена только внутри одного текстового узла, без переносов в исходном фрагменте и замене. Применяются DOM Range и native insertText, события beforeinput/input и проверка точного результата. Весь innerHTML не заменяется. Межузловые/многострочные замены и вставки доступны через ручное копирование. Вопрос с недостающим фактом нельзя принять как замену.

После собственной правки остальные позиции сдвигаются по длине; пересекающиеся замечания отключаются. Пользовательское изменение делает весь результат устаревшим. Отмена работает в обратном порядке только при неизменённом ожидаемом снимке и восстанавливает исходную DOM-строку, включая NBSP. Расширение не отправляет письмо.

Состояние проверки живёт в content script; ключ и счётчики — в локальном хранилище. Запрос ограничен 25 секундами, ниже порога ожидания fetch в MV3. При потере worker показывается ошибка; скрытых повторных запросов нет.
