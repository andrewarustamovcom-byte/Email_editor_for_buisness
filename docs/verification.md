## Автоматические риски

Vitest проверяет контракты, неоднозначные/повторяющиеся цитаты, Unicode, DOM-карту, подпись/цитаты, изменение с возвратом исходного текста, последовательное принятие и отмену, устаревание и подтверждение истории. Прямой клиент проверяется на фиксированный промпт и endpoint, строгую JSON Schema, хеш снимка, HTTP 400/401/403/413/429/500/503, отсутствие повторов, неверный/обрезанный/слишком большой ответ, отказ модели и неподтверждённые цитаты. Секреты и тело ответа провайдера не возвращаются в ошибках.

Локальные лимиты проверяются при одновременных запросах вкладок, перезапуске экземпляра, смене/удалении ключа, дневном и общем пределе, повреждении хранилища и ошибке записи до fetch. В storage остаются только ключ и числовой ledger.

Playwright запускает Chromium на обезличенном Gmail DOM: несколько черновиков; подсветка; сравнение; принятие/отклонение/отмена; сохранение bold, ссылки, подписи и цитаты; изменение во время анализа; выбор/сброс истории; вопрос вместо придуманного срока; неоднозначная цитата; запрет межузловой замены; закрытие редактора; ошибки API/модели.

Отдельный тест загружает собранное MV3-расширение с настоящими worker и options.html. В тестовой копии меняется только адрес Groq на локальный mock endpoint и добавляется probe доступа к storage из реального isolated content world. Проверяются Authorization, промпт, формат запроса, ключ только в trusted storage, отсутствие текстов в storage, правка/отмена, блокировка повторной попытки и сохранение счётчиков после закрытия/повторного запуска браузера.

MockProvider — демонстрационный набор правил для fixtures, не оценка качества облачной модели. Семантика пяти категорий и устойчивость к инструкциям внутри письма требуют настоящего smoke и оценки человеком.

## Следующая внешняя проверка

1. Создать личный ключ Groq в аккаунте Free и сохранить в настройках готового расширения.
2. Открыть обезличенный черновик в настоящем Gmail и выполнить проверку.
3. Проверить категории, точность цитат, минимальность правок и отсутствие придуманных сроков/сумм.
4. Проверить информационное письмо без поручения, отсутствие/неполноту истории, инструкции внутри текста письма.
5. Проверить обычный compose и inline reply, несколько черновиков, форматирование, ссылки, подпись, цитаты, emoji и NBSP.
6. Изменить/закрыть черновик во время ответа, принять две правки и отменить обе; проверить сохранение черновика Gmail.
7. Проверить 429 и недоступность сети: без автоматических повторов и самопроизвольных изменений.

Разработчик может выполнить `npm run smoke:live` с GROQ_API_KEY в `.env`: один обезличенный запрос, проверка схемы/цитат, без вывода ключа и текста. Этот запрос не выполняется в CI. Он подчиняется тарифу и квотам аккаунта владельца ключа.
